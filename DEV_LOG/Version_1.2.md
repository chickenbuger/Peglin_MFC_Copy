# Version 1.2 — 게임 모델과 뷰 책임 분리

## 버전 정보

| 항목 | 값 |
| --- | --- |
| 버전 | Version 1.2 |
| 스프린트 | Sprint 1 |
| 작업일 | 2026-08-29 (Asia/Seoul) |
| 목적 | 물리·충돌·전투·상태 전이를 MFC 창의 입력·렌더링 책임에서 분리 |
| 판정 | **완료 — `GameWorld` 분리 및 전체 빌드·실행 회귀 통과** |

## 변경 사항

- `GameWorld`를 추가해 플레이어, 적, 공, 페그 목록과 게임 상태를 소유하도록 했다.
- 공 업데이트, 페그 충돌, 피해 누적, 화면 이탈, 적 이동, 플레이어 피해와 승패 판정을 `GameWorld::Update()`로 이동했다.
- 조준 시작·추적·발사·취소와 일시정지·초기화 API를 모델에 캡슐화했다.
- `GameUpdateResult`로 승리·패배 결과만 뷰에 전달해 대화상자 표시는 Windows 계층에 남겼다.
- `CChildView`에는 고정 타이머, Windows 메시지 입력, 더블 버퍼 렌더링과 결과 대화상자 처리만 남겼다.
- 보드와 전투 상수를 `GameWorld.cpp`의 모델 범위로 이동했다.

## 검증

- `GameWorld.h/.cpp`에서 `CWnd`, `CDC`, `AfxMessageBox`, `OnPaint`, `OnTimer` 참조가 0개임을 확인했다.
- `CChildView`에서 페그 충돌, 누적 피해, 턴 정산과 상태 전이 구현 참조가 0개임을 확인했다.
- Debug/Release × x64/x86 네 구성 `/W4` 재빌드 성공: 오류 0개, 자체 코드 경고 0개.
- Debug x64 실제 창에서 초기 48개 페그 렌더링, 드래그 발사, 페그 1개 제거, 적 체력 `20→19`, 공 초기 위치와 조준 상태 복귀를 확인했다.
- 오류 대화상자 없이 정상 종료했다.

## 결론

MFC 메시지 루프 없이도 호출할 수 있는 게임 모델 경계가 생겼다. 다음 단계에서는 모델 내부의 raw 좌표 배열과 축별 속도 API를 2D 벡터 값 타입으로 교체한다.
