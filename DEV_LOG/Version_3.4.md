# Version 3.4 — 난이도와 접근성 옵션

| 항목 | 값 |
| --- | --- |
| 버전 | Version 3.4 |
| 스프린트 | Sprint 3 |
| 작업일 | 2026-08-29 (Asia/Seoul) |
| 상태 | 구현 및 검증 완료 |

## 구현 이유

- 스테이지 규칙은 데이터화됐지만 사용자가 플레이 강도를 선택하는 UI와 일관된 난이도 적용 경로가 없었다.
- 페그를 색만으로 구분하면 색각 차이가 있는 사용자가 Critical, Bomb과 Refresh를 빠르게 판별하기 어렵다.
- 사운드 토글이 게임 중 단축키로만 제공되어 시작 전에 옵션을 확인하고 설정하기 어려웠다.

## 구현 내용

- 스테이지 선택 화면의 `[O]`에서 독립된 옵션 화면으로 진입한다.
- `[D]`로 쉬움·보통·어려움을 순환하고 선택 화면에서 조정된 적 체력과 이동 횟수를 미리 보여 준다.
- 쉬움은 적 체력 80%, 플레이어 피해 75%, 공격 전 이동 +2를 적용한다.
- 어려움은 적 체력 150%, 플레이어 피해 125%, 공격 전 이동 -2를 적용한다.
- `[M]`으로 사운드를 끄거나 켜고, 게임 중 `M` 단축키와 같은 옵션 값을 공유한다.
- `[C]`로 표준 색상과 고대비+모양 모드를 전환한다.
- 고대비 모드는 Normal 파랑 선, Critical 노랑 십자, Bomb 흰색 X, Refresh 청록 고리로 색과 형태를 함께 구분한다.
- 옵션은 스테이지 시작, 새 게임과 결과 화면 재도전 동안 유지한다.
- 앱을 완전히 재실행하면 보통·사운드 켜짐·표준 색상의 안전한 기본값으로 시작한다.
- 난이도는 검증된 기본 스테이지의 수치만 변환하고 좌표·페그 효과·점수 규칙에는 영향을 주지 않는다.

## 자동화 검증

- 옵션 기본값과 난이도·사운드·색상 모드의 순환 및 양방향 토글을 확인했다.
- 쉬움 stage-1이 적 체력 16, 피해 15, 이동 10으로 계산되는지 검증했다.
- 어려움 stage-1이 적 체력 30, 피해 25, 이동 6으로 계산되는지 검증했다.
- 두 난이도 정의가 스테이지 검증을 통과하고 재도전 후에도 유지되는지 확인했다.
- 보통 난이도로 다시 로드하면 원래 적 체력 20으로 복원되는지 검증했다.
- Debug/Release × x64/x86 빌드 성공, 오류 0개, 프로젝트 자체 경고 0개다.
- `PeglinCoreTests`: 구성별 `272 PASS / 0 FAIL`, 네 구성 총 1,088개 통과다.

## 실제 실행 검증

- Release x64 옵션 화면에서 어려움·사운드 꺼짐·고대비+모양을 선택했다.
- 선택 화면 수치가 stage-1 `Enemy HP 30 · 6 Steps`, stage-2 `Enemy HP 45 · 4 Steps`로 변경됐다.
- stage-1 시작 후 적 체력 30과 48개 고대비 페그가 표시됐다.
- Normal·Critical·Bomb·Refresh가 파랑 선·노랑 십자·흰색 X·청록 고리로 구분됐다.
- 오류 대화상자, ASSERT와 잔류 프로세스 없이 정상 종료했다.
