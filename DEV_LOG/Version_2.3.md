## 구현 이유

- 보드 좌표를 코드에서 주입할 수는 있었지만 보드, 적과 턴 규칙을 하나의 콘텐츠 단위로 불러오는 경로가 없었다.
- 잘못된 스테이지가 게임 상태에 일부만 적용되면 화면 밖 충돌, 즉시 승패와 초기화 불일치가 생길 수 있어 객체 생성 전 검증이 필요했다.

## 스테이지 구조

- `StageDefinition`: 스테이지 ID, 표시 이름, 페그 보드와 규칙을 한 단위로 보관
- `StageRules`: 플레이어·적 체력, 적 공격 피해, 공격 전 이동 횟수, 이동 거리와 페그 반발계수
- `LoadStageDefinition(id)`: 내장 카탈로그에서 스테이지를 불러오고 검증을 통과한 경우에만 완전한 정의 반환
- `ValidateStageDefinition()`: ID, 보드 크기, 좌표, 중복, 페그 종류와 모든 수치 규칙 검증

## 내장 스테이지

| ID | 보드 | 적 체력 | 공격 피해 | 이동 후 공격 | 반발계수 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `stage-1` | 기본 48개 | 20 | 20 | 8회 | 0.85 |
| `stage-2` | 시드 고정 40개 | 30 | 25 | 6회 | 0.90 |

## 안전한 실패 규칙

- 존재하지 않는 ID는 `NotFound`를 반환하고 스테이지 값을 만들지 않는다.
- 빈 ID·빈 보드·256개 초과 보드·화면 밖 좌표·중복 좌표·알 수 없는 페그 종류를 거부한다.
- 0 이하 또는 비정상 체력·피해·턴·이동 수치와 `0~1` 밖 반발계수를 거부한다.
- 검증 실패 시 부분적으로 채워진 `StageDefinition`을 호출자에게 반환하지 않는다.

## GameWorld 적용

- 기본 게임도 `stage-1` 로딩 경로를 통해 생성된다.
- 스테이지 보드와 플레이어·적 체력, 적 이동·공격 규칙, 반발계수를 초기화에 적용한다.
- 새 게임 시 같은 스테이지 규칙으로 체력, 보드와 반발계수를 다시 복원한다.
- 기존 `PegLayoutDefinition` 생성자는 사용자 정의 테스트와 호환되도록 `custom` 스테이지로 변환한다.

## 검증 결과

### 자동 검증

- Debug/Release × x64/x86 앱 및 테스트 빌드 성공
- 오류 0개, 프로젝트 자체 경고 0개
- `PeglinCoreTests`: 구성별 155 PASS, 0 FAIL, 총 620 PASS
- `stage-1`·`stage-2` 카탈로그 로딩과 서로 다른 보드·적·턴 규칙 확인
- 미등록 ID, 빈 ID·보드, 화면 밖·중복 페그, 유효하지 않은 적 체력·턴·반발계수 실패 확인
- 사용자 스테이지의 플레이어 75, 적 9, 이동 10, 공격 피해 15와 반발계수 0.5 적용 확인
- 새 게임 후 사용자 스테이지 규칙 복원 확인

### 실제 실행 검증

- x64 Release 기본 게임에서 `stage-1`의 플레이어 체력 100, 몬스터 체력 20과 48개 보드가 정상 표시됐다.
- 네 종류 페그 색상, 점수 피드백과 기존 레이아웃이 유지됐다.
- 오류 대화상자 없이 정상 기동·종료됐고 잔류 프로세스가 없었다.
