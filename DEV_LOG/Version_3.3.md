# Version 3.3 — 스테이지 선택과 결과 화면

## 버전 정보

| 항목 | 값 |
| --- | --- |
| 버전 | Version 3.3 |
| 스프린트 | Sprint 3 |
| 작업일 | 2026-08-29 (Asia/Seoul) |
| 상태 | 구현 및 검증 완료 |

## 구현 이유

- `stage-1`과 `stage-2` 데이터가 존재해도 앱은 항상 기본 스테이지를 바로 실행해 두 콘텐츠를 선택할 수 없었다.
- 승패 결과를 모달 대화상자로만 보여 주면 점수·최고 콤보·턴을 비교하기 어렵고 재도전과 다른 스테이지 선택의 흐름도 분리되지 않는다.

## 구현 내용

- 검증된 두 스테이지의 ID와 표시 이름을 `StageCatalogEntry` 목록으로 제공한다.
- `GameWorld::LoadStage()`는 등록된 정의를 검증한 뒤에만 현재 스테이지를 교체하고, 실패하면 기존 상태를 보존한다.
- 앱 시작 시 `SELECT STAGE` 화면을 표시하고 숫자 `1` 또는 `2`로 스테이지를 시작한다.
- stage-1은 48개 페그·적 체력 20·8회 이동, stage-2는 40개 페그·적 체력 30·6회 이동 정보를 선택 전에 보여 준다.
- 플레이 중 조준 상태에서 `S`를 누르면 스테이지 선택 화면으로 돌아간다.
- 승패 시 모달 메시지 대신 `STAGE CLEAR` 또는 `GAME OVER` 결과 화면으로 전환한다.
- 결과 화면은 스테이지, 최종 점수, 최고 콤보와 턴을 보존하고 `[R]` 재도전, `[S]` 스테이지 선택을 제공한다.
- 결과 화면에서는 게임 모델 업데이트를 멈춰 종료 결과가 반복 처리되지 않는다.
- 결과 요약의 const 조회를 위해 `Enemy` 조회 API를 const-safe하게 정리했다.

## 자동화 검증

- 카탈로그에 안정적인 `stage-1`, `stage-2` ID 두 개만 있는지 확인했다.
- 미등록 ID 거부 시 현재 스테이지가 바뀌지 않는지 검증했다.
- stage-2 선택 시 40개 페그, 적 체력 30과 재도전 시 선택 유지 여부를 확인했다.
- 승리 결과에 스테이지 ID, 점수 200, 최고 콤보 1과 턴 1이 보존되는지 검증했다.
- 종료 결과가 이전과 같이 한 번만 반환되는지 확인했다.
- Debug/Release × x64/x86 빌드 성공, 오류 0개, 프로젝트 자체 경고 0개다.
- `PeglinCoreTests`: 구성별 `248 PASS / 0 FAIL`, 네 구성 총 992개 통과다.

## 실제 실행 검증

- Release x64 시작 시 두 스테이지의 이름·페그 수·적 체력·이동 횟수가 구분된 선택 화면을 확인했다.
- `2` 입력 후 Dense Cavern의 적 체력 30과 불규칙한 40개 페그 보드가 표시됐다.
- 조준 상태의 `S` 입력으로 선택 화면에 안전하게 복귀했다.
- 오류 대화상자, ASSERT와 잔류 프로세스 없이 정상 종료했다.
