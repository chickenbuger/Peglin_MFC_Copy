## 요약

현재 프로젝트는 MFC 단일 창 애플리케이션으로, Peglin의 핵심 형태인 공 발사, 중력, 벽 반사, 페그 충돌, 누적 피해, 적 이동, 플레이어 피격, 승패 및 재시작 흐름을 구현한 프로토타입이다. 클래스가 기능별로 나뉘어 있고 더블 버퍼링을 사용해 기본적인 게임 화면 구조도 갖추고 있다.

다만 현재 PC에서는 Visual Studio 2022와 v143 컴파일러는 확인되지만 MFC 라이브러리 구성요소가 설치되어 있지 않아 빌드가 `MSB8041` 오류로 중단된다. 저장소에도 실행 파일은 없고 PDB 등 과거 빌드 산출물만 남아 있으므로, **현재 체크아웃을 그대로 빌드해 실행할 수 있는 상태라고 판단할 수 없다.** Sprint 0은 이 재현성 문제와 최소 실행 안정성 문제를 해결한 뒤 종료해야 한다.

## 현재 구현 기능

### 게임 흐름

1. 고정 크기 게임 창을 생성한다.
2. 화면 상단에 플레이어와 적을 표시하고, 하단 보드에 빨간 페그를 배치한다.
3. 마우스 드래그 방향과 길이로 발사 방향·세기를 계산한다.
4. 공에 중력을 적용하고 좌·우 벽 및 천장 충돌 시 속도 방향을 바꾼다.
5. 공이 페그와 충돌하면 페그를 제거하고 피해량을 1 증가시킨다.
6. 공이 화면 아래로 떨어지면 누적 피해를 적에게 적용한다.
7. 턴이 지나면 적이 플레이어에게 접근하고, 일정 횟수 이후에는 플레이어 체력을 감소시킨다.
8. 적 체력이 0 이하이면 게임 클리어, 플레이어 체력이 0 이하이면 게임 오버 메시지를 표시한 뒤 상태를 초기화한다.

### 입력

| 입력 | 동작 |
| --- | --- |
| 마우스 왼쪽 버튼 드래그 후 놓기 | 조준 및 공 발사 |
| `Space` | 공 이동 일시정지/재개 |
| `F5` | 공 위치 초기화 |
| 메뉴의 `새 게임` | 전체 게임 상태 초기화 |

## 잘 구현된 부분

- 플레이어, 적, 공, 페그, 배경을 별도 클래스로 분리해 초기 구조를 잡았다.
- `OnPaint`에서 메모리 DC로 먼저 그린 뒤 `BitBlt`하는 더블 버퍼링을 적용해 직접 그리기보다 깜빡임을 줄였다.
- 원 충돌 판정에서 먼저 제곱 거리를 비교하고 실제 충돌 시에만 제곱근을 계산한다.
- 충돌 거리 0일 때 나눗셈을 피하는 방어 코드가 있다.
- 발사 세기를 최소·최대 범위로 제한하고, 게임 상태 초기화 경로를 한 함수로 모았다.
- Debug/Release 및 Win32/x64 구성이 솔루션에 모두 선언되어 있다.

## 빌드 및 실행 검증

### 확인된 로컬 도구

- Visual Studio Community 2022 17.14.21
- MSBuild 17.14.23
- 프로젝트 요구 도구 집합: v143

### 수행 명령

```powershell
& 'C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe' `
  '.\FinalProject_Peglin.sln' /m /t:Build `
  /p:Configuration=Debug /p:Platform=x64 /v:minimal
```

### 결과

```text
error MSB8041: 이 프로젝트에는 MFC 라이브러리가 필요합니다.
사용되는 모든 도구 세트 및 아키텍처의 경우 Visual Studio 설치 관리자에서 설치하세요.
```

- 최초 샌드박스 실행에서는 Windows SDK 사용자 설정 경로 접근 제한이 있었으며, 권한을 허용한 실제 빌드에서도 위 MFC 구성요소 누락 오류가 재현되었다.
- `FinalProject_Peglin/x64/Debug/FinalProject_Peglin.log`에는 과거 `D:\Project\MFC\...` 위치에서 x64 Debug 빌드가 성공한 기록이 있다. 당시에는 형 변환 경고 `C4244`와 잘못된 엔트리 포인트 지정에 따른 `LNK4258` 경고가 발생했다.
- `FinalProject_Peglin/Debug/FinalProject_Peglin.log`에는 Win32 빌드가 MFC 누락으로 실패한 기록이 있다.
- 현재 저장소에는 실행 가능한 `.exe`가 없고 PDB, TLOG, ILK, APS, VS 사용자 캐시 등 과거 산출물이 다수 추적되고 있다.

따라서 Version 0.1의 빌드 상태는 **실패**, 실행 스모크 테스트는 **미수행**이다.

## 개선이 필요한 부분과 이유

### P0 — Sprint 0 완료를 막는 항목

| 항목 | 근거 | 개선이 필요한 이유 |
| --- | --- | --- |
| MFC 빌드 구성요소 누락 | 현재 x64 Debug 빌드가 `MSB8041`로 종료됨 | 소스 변경과 무관하게 실행 파일을 만들 수 없어 모든 기능 검증이 막힌다. |
| 구성별 C++ 표준 불일치 | C++20은 Debug x64에만 지정되지만 `std::clamp`는 공통 소스에서 사용됨 | Debug x64만 우연히 통과하고 Release/Win32가 다른 결과를 내는 구성 드리프트가 발생할 수 있다. |
| 0 길이 드래그 나눗셈 | `Parent_ball::shooting()`이 길이 검사 전에 방향 벡터를 길이로 나눔 | 같은 지점에서 누르고 놓으면 속도에 NaN이 들어가 공이 정상 상태로 복구되지 않을 수 있다. |
| GDI 객체 선택 상태 미복원 | 프레임마다 생성한 비트맵·브러시·펜을 DC에 선택한 뒤 이전 객체를 복원하지 않음 | 선택된 GDI 객체는 정상 삭제되지 않아 10ms 주기 렌더링에서 핸들 누수와 장시간 실행 불안정을 일으킬 수 있다. |
| 타이머 식별과 루프 분리 | 같은 10ms 주기의 타이머 ID 0과 1을 만들고 반환 ID를 저장하지 않음 | ID 0은 시스템이 실제 ID를 정할 수 있고, 두 타이머의 충돌·이동 처리 순서도 보장되지 않아 게임 결과가 환경에 따라 달라질 수 있다. |

### P1 — 기본 플레이 안정성과 품질에 직접 영향

| 항목 | 근거 | 개선이 필요한 이유 |
| --- | --- | --- |
| 페그 배치 수식 오류 | 열 반복 횟수는 40 간격으로 계산하지만 실제 x 간격은 80이며, 총 88개 중 40개가 x=1010~1730에 생성됨 | 고정 폭 1000 창 밖의 페그는 도달하거나 볼 수 없고 불필요한 갱신·렌더링 비용만 만든다. |
| 충돌 반응의 에너지 소실 | 정지한 페그와 같은 질량의 속도 교환을 계산한 뒤 페그를 즉시 제거해 공의 법선 속도가 0이 됨 | 공이 튕기기보다 접선 방향으로 미끄러져 Peglin형 반사 감각과 다르게 동작한다. 반발계수를 둔 반사식이 필요하다. |
| 프레임 시간 미사용 | 이동·중력이 타이머 호출 횟수에 직접 의존함 | PC 부하, 메시지 큐 지연, 타이머 해상도에 따라 속도와 궤적이 달라진다. 고정 시간 간격 또는 누적 시간 기반 업데이트가 필요하다. |
| 마우스 포커스 처리 미연결 | `CChildView`에 `OnSetFocus`/`OnKillFocus` 구현은 있지만 메시지 맵 항목이 없음 | 의도한 커서 제한·해제가 호출되지 않을 수 있고, 포커스 상실 시 커서가 제한된 채 남는 위험이 있다. |
| 드래그 캡처 없음 | 버튼을 누른 뒤 `SetCapture`/`ReleaseCapture`를 사용하지 않음 | 창 밖에서 버튼을 놓으면 발사 종료 이벤트를 받지 못해 입력 상태가 꼬일 수 있다. |
| 초기화 상태 불완전 | `Parent_ball::Init()`이 속도, 힘, 클릭, 드래그 좌표를 모두 초기화하지 않음 | 재시작이나 F5 이후 이전 입력·물리 상태가 다음 발사에 섞일 수 있다. |
| 자체 코드 경고 존재 | 과거 성공 로그에 여러 `C4244`와 모든 객체의 `LNK4258` 기록이 있음 | 좌표 정밀도 손실을 숨기고, Debug 콘솔 엔트리 포인트 설정이 실제로 무시되어 디버깅 의도와 실행 구성이 다르다. |
| 자동 검증 부재 | 물리·전투 계산이 UI 클래스와 결합되어 있고 테스트 프로젝트가 없음 | 충돌이나 턴 로직을 수정해도 기존 동작이 유지되는지 빠르게 확인하기 어렵다. |

## Version 0.1 결론

- 현재 코드는 Peglin형 게임의 핵심 상호작용을 보여 주는 **기능 프로토타입**이다.
- 현재 작업 폴더는 MFC 구성요소 누락 때문에 **재현 가능한 실행 상태가 아니다**.
- Sprint 0은 아직 완료되지 않았으며 Sprint 1로 전환하면 안 된다.
- 다음 작업은 [Next Version Plan 0](./Next_Version_Plan_0.md)의 필수 항목을 순서대로 처리하고, 깨끗한 환경에서 빌드·실행·기본 플레이를 검증하는 것이다.
