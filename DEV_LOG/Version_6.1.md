## 개선 이유

Version 5.5의 메뉴 화면은 공통 프레임과 패널을 갖췄지만 실제 플레이 화면은 512×214 타일 배경, 64×64 임시 캐릭터 이미지, 단색 회색 원형 공과 검은 플레이필드에 머물렀다. 화면 간 시각 품질 차이가 크고, 공이 발사 준비 상태인지 움직이는 중인지 정지 화면만으로 빠르게 파악하기 어려웠다.

따라서 이번 버전은 물리·충돌 규칙은 유지하면서 플레이 화면의 이미지 자산과 공의 시각 피드백을 함께 개선했다.

## 구현 내용

### 1. ImageGen 게임플레이 자산

Codex 내장 ImageGen으로 기존 `ui-adventure-frame-v1.bmp`의 어두운 남청색 동굴과 황금 조명 화풍을 이어가는 네 자산을 생성했다.

| 자산 | 투명 원본 | MFC 런타임 자산 | 런타임 크기 |
| --- | --- | --- | --- |
| 전체 플레이 배경 | `gameplay-cave-v2-source.png` | `gameplay-cave-v2.bmp` | 1000×800 |
| 숲 고블린 플레이어 | `player-hero-v2-source.png` | `player-hero-v2.bmp` | 104×108 |
| 수정 두꺼비 몬스터 | `enemy-crystal-toad-v2-source.png` | `enemy-crystal-toad-v2.bmp` | 132×106 |
| 호박·청록 마법 공 | `orb-amber-teal-v2-source.png` | `orb-amber-teal-v2.bmp` | 36×36 |

- PNG 원본의 알파 채널을 보존했다.
- 현재 MFC GDI 경로에서는 축소한 24-bit BMP와 순수 마젠타 색상 키를 사용한다.
- 생성 방식, 최종 프롬프트와 변환 규칙을 `res/gameplay-art-v2.prompt.md`에 기록했다.
- 배경에는 페그·공·문자·컨트롤을 그리지 않아 런타임 오브젝트와 겹치지 않게 했다.

### 2. 플레이 배경과 상단 캐릭터 배치

- 검은 하단 영역을 은은한 석재 질감의 남청색 동굴 플레이필드로 교체했다.
- 상단 왼쪽과 오른쪽의 석재 발판에 플레이어와 몬스터가 올라서도록 크기·위치를 조정했다.
- 공 초기 위치와 일치하는 중앙 생성 포털을 배경에 배치했다.
- 페그가 묻히지 않도록 하단 중앙의 장식과 광원을 제한하고 외곽 뿌리·수정에만 강조를 뒀다.

### 3. 관리되는 GDI 이미지 수명

- 배경·플레이어·몬스터·공 비트맵을 `OnCreate`에서 한 번 로드하고 `OnDestroy`에서 해제한다.
- 배경은 메모리 DC에서 전체 클라이언트로 복사한다.
- 캐릭터·몬스터·공은 `TransparentBlt`로 마젠타 배경을 제거해 합성한다.
- 선택한 비트맵과 브러시는 사용 직후 원래 GDI 객체로 복원한다.
- 새 리소스를 `UiResources.rc`에 포함해 별도 외부 이미지 파일 없이 실행 파일에서 로드한다.

### 4. 공 배치와 움직임 개선

- 조준 대기 중 공이 중앙 포털 안에서 4px 범위로 천천히 위아래로 부유한다.
- 같은 상태에서 약 5.5% 크기 맥동을 적용해 발사 가능한 오브임을 보여준다.
- 발사 후 25ms 간격으로 최대 12개 위치를 수집하고 0.24초 동안 청록색 잔상을 그린다.
- 잔상은 오래될수록 작고 어두워져 공의 진행 방향을 읽을 수 있다.
- 부유·맥동·잔상은 렌더링 좌표에만 적용하며 공의 물리 위치, 반지름, 충돌 및 피해 계산은 변경하지 않았다.
- 페그를 먼저 그리고 잔상과 공을 나중에 그려 공이 플레이 오브젝트 위에서 명확히 보이게 했다.

## 검증 결과

### 빌드와 자동 테스트

| 구성 | 앱·테스트 빌드 | 자체 경고 | 코어 테스트 |
| --- | --- | --- | --- |
| Debug x64 | 성공 | 0 | 512/512 통과 |
| Release x64 | 성공 | 0 | 512/512 통과 |
| Debug x86 | 성공 | 0 | 512/512 통과 |
| Release x86 | 성공 | 0 | 512/512 통과 |

- 합계 2,048개 검증 통과, 실패 0개.
- `diff --check`에서 공백 오류가 없었다.
- 이미지 변경 뒤 기존 발사·충돌·턴·승리·패배·단일 결과·외부 콘텐츠 검증이 모두 유지됐다.

### 실제 창 검증

Debug x64 실제 MFC 창에서 다음을 직접 확인했다.

- 스테이지 선택 후 전체 동굴 배경이 1000×800 클라이언트를 채운다.
- 플레이어와 몬스터가 각 상단 발판 안에 표시되고 마젠타 배경이나 사각 테두리가 남지 않는다.
- 체력·상태·다음 행동·장비 텍스트가 어두운 배경에서 밝게 읽힌다.
- 공이 중앙 생성 포털 안에서 부유하고, 드래그 발사 후 마법 공과 청록색 잔상이 진행 방향을 따라 움직인다.
- 페그 48개와 기존 특수 페그 색상은 새 배경 위에서 구분된다.
- 오류·ASSERT·예외 대화상자 없이 정상 종료했다.

Sprint 6 종료용 10분 GDI·최종 패키지 검증은 남은 P0 기능을 모두 구현한 뒤 최종 게이트에서 다시 수행한다.
