## 개선 이유

기존 Refresh Peg는 턴이 지나도 같은 위치에 남고 직접 적중하면 원래 위치로 복원됐다. 한 번 위치를 파악하면 이후 턴의 조준 경로가 반복되었으며, 폭발로 제거된 경우에는 공격이 끝날 때까지 보드에서 사라졌다. 매 턴 Refresh 위치가 바뀌고 파괴된 Refresh가 즉시 다른 위치에 나타나도록 변경해 매 공격마다 보드 경로를 다시 판단하게 했다.

## 구현 내용

- 턴 정산 마지막에 모든 활성 Refresh Peg와 다른 활성 페그의 타입을 교환해 원본 페그 수·좌표·이동 궤도를 유지하면서 위치만 변경한다.
- 스테이지 ID 해시, 완료 턴과 재배치 횟수로 후보 시작점을 결정해 같은 입력에서 결과를 재현할 수 있게 했다.
- Refresh가 직접 적중하면 제거된 페그를 원본 인덱스로 복원한 직후 Refresh를 이전과 다른 활성 페그 위치로 옮긴다.
- 폭발 범위로 Refresh가 제거되면 같은 충돌 처리 안에서 다른 위치에 즉시 다시 만든다.
- 스테이지 정의에 포함된 Refresh 개수를 전투 중 유지한다. 원래 Refresh가 없는 사용자 정의 배치는 최소 한 개를 보장한다.
- 기존 Refresh 위치는 재생성 후보의 마지막 순위로 두어 다른 유효 위치가 있으면 이전 자리로 돌아가지 않게 했다.
- `RefreshRelocated` 이벤트와 `REFRESH MOVED` 피드백을 추가해 위치 변경 결과를 화면에서 알 수 있게 했다.
- 다른 위치가 존재하지 않는 단일 페그 사용자 정의 배치에서는 불가능한 재배치를 생략하고 최소 한 개 불변 조건을 유지한다.

## Refresh 처리 순서

1. 직접 적중한 Refresh는 제거된 보드를 먼저 복원한다.
2. 폭발로 제거됐거나 복원 뒤 부족한 Refresh 개수를 다른 원본 인덱스에 즉시 보충한다.
3. 유효한 비-Refresh 활성 페그와 타입을 교환해 이전과 다른 위치로 이동한다.
4. 해당 공격에서 이미 재배치했다면 턴 종료 시 중복 이동하지 않는다.
5. 공격 중 Refresh가 파괴되지 않았다면 턴 종료마다 한 번 재배치한다.
