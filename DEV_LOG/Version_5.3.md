## 구현

- `content/stages.v1.ini`에 세 스테이지의 보드, 페그 종류, 체력·턴 규칙과 보스 행동 패턴을 분리했다.
- 파일 전체가 검증된 경우에만 외부 카탈로그를 노출하고, 하나라도 실패하면 부분 결과를 버리고 검증된 내장 3개 스테이지로 복구한다.
- 앱은 실행 파일 옆 `content/stages.v1.ini`를 읽고 선택 화면과 `GameWorld`에 해당 정의를 실제 주입한다.
- `GameWorld::LoadStage(const StageDefinition&, ...)`를 추가해 등록된 외부 정의에도 기존 난이도 적용과 최종 검증을 동일하게 수행한다.
- 버전 1 형식은 다음을 지원한다.
  - 안정적인 스테이지 ID와 UTF-8 표시 이름
  - 시드·격자·간격·흔들림 기반 보드와 인덱스별 페그 종류 재정의
  - 플레이어·적 체력, 적 피해·이동·턴, 반발계수
  - 보스 표시와 순서가 보존되는 이동·방어·공격 행동
- 개발 빌드의 네 출력 폴더와 Release x64 배포 패키지에 콘텐츠 파일을 자동 복사한다.
- 배포 사전 검사가 중첩 경로의 SHA-256도 계산하며 콘텐츠 누락·변조를 실패로 탐지한다.

## 거부·복구 정책

- 누락·I/O 실패, 256KiB 초과, 잘못된 UTF-8과 지원하지 않는 버전을 거부한다.
- 알 수 없는 키·행동·페그 종류, 중복 스칼라 키·페그 재정의·스테이지 ID를 거부한다.
- 필수 필드 누락, 닫히지 않은 섹션, 숫자 파싱 실패·비정상 값과 화면 밖 보드를 거부한다.
- 실패 결과에는 외부 파일의 일부 스테이지를 섞지 않고 오류 종류·행 번호와 내장 카탈로그만 제공한다.
- 선택 화면은 복구 실행 중임을 알리는 안내를 표시한다.

## 빌드·테스트

- Debug/Release × x64/x86 앱·테스트 빌드 성공.
- 네 구성 모두 오류 0개, 프로젝트 자체 경고 0개.
- 구성별 `481 PASS / 0 FAIL`, 총 `1,924 PASS / 0 FAIL`.

- 정상 사용자 정의 스테이지를 Hard 난이도로 실제 `GameWorld`에 로드해 체력 67.5와 행동 순서를 확인했다.
