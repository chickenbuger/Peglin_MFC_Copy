## 우선순위

### P0 — Sprint 1 완료 필수

- [x] **게임 상태 열거형과 명시적 상태 전이를 도입한다.**
  - 이유: 현재 조준, 발사, 낙하, 피해 정산, 승리·패배가 여러 플래그와 화면 코드에 흩어져 있어 순서 오류를 만들기 쉽다.
  - 완료 기준: `조준 → 발사 → 낙하 → 피해 정산 → 다음 턴/승리/패배` 흐름이 단일 상태 전이 규칙으로 표현된다.
- [x] **물리 계산과 전투 규칙을 `CChildView`의 입력·렌더링 책임에서 분리한다.**
  - 이유: 화면 메시지 처리와 게임 규칙이 결합되어 자동 검증과 기능 확장이 어렵다.
  - 완료 기준: 창이나 GDI 객체 없이 공 이동, 페그 충돌, 턴 정산을 실행할 수 있다.
- [x] **`float[2]`와 raw 포인터 좌표 API를 2D 벡터 값 타입으로 교체한다.**
  - 이유: 배열 인덱스와 포인터 별칭은 좌표 의미를 흐리고 잘못된 수명·축 사용을 컴파일 단계에서 막지 못한다.
  - 완료 기준: 위치·속도·힘·법선 계산이 이름 있는 벡터 연산으로 표현되고 raw 포인터 getter가 제거된다.
- [x] **법선 반사와 조정 가능한 반발계수로 공·페그 충돌을 개선한다.**
  - 이유: 현재 충돌 응답은 Peglin형 튕김 감각과 물리 일관성이 부족하다.
  - 완료 기준: 접근 중인 공에만 충돌 응답이 적용되고 겹침 보정, 반사 방향, 에너지 유지 정도가 수치로 검증된다.
- [x] **핵심 물리와 턴 계산에 자동화 테스트를 추가한다.**
  - 이유: Sprint 1 구조 변경이 발사 방향, 충돌 피해, 턴 진행을 깨뜨리지 않았음을 반복 확인해야 한다.
  - 완료 기준: 0 길이 발사, 벽 반사, 페그 1회 충돌, 화면 이탈, 승리·패배 전이를 테스트한다.

### P1 — P0 완료 후 진행

- [x] 보드, 벽, 캐릭터 좌표와 크기를 하나의 레이아웃 설정으로 통합한다.
  - 이유: 화면 상수가 분산되면 해상도나 보드 구성 변경 시 서로 어긋난다.
- [x] 상태와 충돌 이벤트를 이용해 피해·턴 전환 피드백을 명확히 표시한다.
  - 이유: 현재 결과가 즉시 바뀌어 플레이어가 원인을 파악하기 어렵다.
- [x] 테스트 가능한 난수와 데이터 기반 페그 배치 경로를 마련한다.
  - 이유: 향후 다양한 보드와 재현 가능한 테스트를 함께 지원해야 한다.
