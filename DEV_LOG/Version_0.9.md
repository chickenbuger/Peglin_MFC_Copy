# Version 0.9 — 포커스와 마우스 캡처 안전 처리

## 버전 정보

| 항목 | 값 |
| --- | --- |
| 버전 | Version 0.9 |
| 스프린트 | Sprint 0 |
| 작업일 | 2026-08-29 (Asia/Seoul) |
| 목적 | 창 경계와 포커스 변화에도 드래그 입력 상태를 안전하게 종료 |
| 판정 | **입력 캡처 수명 관리 완료** |

## 변경 사항

- `WM_SETFOCUS`, `WM_KILLFOCUS`, `WM_CAPTURECHANGED` 메시지를 실제 핸들러에 연결했다.
- 발사 가능한 상태에서 마우스 버튼을 누른 경우에만 `SetCapture()`를 호출한다.
- 버튼 해제, 포커스 상실, 캡처 변경, 창 종료에서 클릭 상태와 캡처를 정리한다.
- 기존의 포커스 시 전역 커서 제한을 제거하고 모든 해제 경로에서 `ClipCursor(nullptr)`를 보장한다.
- 사전 클릭이 없는 버튼 해제는 발사로 처리하지 않는다.

## 검증

- Debug/Release × x64/x86 네 구성 재빌드 성공.
- 게임 영역에서 시작해 제목 표시줄에서 버튼을 놓아도 발사가 처리돼 창 경계 해제 메시지 수신을 확인했다.
- 위 동작 직후 `F5` 초기화와 두 번째 정상 드래그 발사가 동작해 입력 상태가 남지 않음을 확인했다.
- `Alt+Tab` 포커스 전환 후 게임 창으로 정상 복귀했고, 창 종료 후 게임 창이 남지 않았다.

## 결론

드래그 수명이 창 내부의 마우스 이동에 의존하지 않으며, 포커스나 창 수명 변화 뒤에도 캡처·클릭·커서 제한 상태가 잔류하지 않는다.
