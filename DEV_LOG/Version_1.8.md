# Version 1.8 — 재현 가능한 데이터 기반 페그 배치

## 버전 정보

| 항목 | 값 |
| --- | --- |
| 버전 | Version 1.8 |
| 스프린트 | Sprint 1 |
| 작업일 | 2026-08-29 (Asia/Seoul) |
| 목적 | 다양한 보드 구성을 데이터로 주입하고 명시적 시드로 같은 변형 배치를 재현 |
| 판정 | **완료 — 빌드·자동 테스트·기본 배치 화면 검증 통과** |

## 변경 사항

- 페그 좌표 목록을 보관하는 `PegLayoutDefinition`을 추가했다.
- 행·열·시작점·간격으로 정규 격자를 만드는 `CreateGridPegLayout()`을 추가했다.
- `std::mt19937`와 명시적 `uint32_t` 시드를 사용하는 `CreateSeededPegLayout()`을 추가했다.
- 난수 오프셋은 직접 정규화해 같은 표준 생성기 출력이 같은 좌표 계산으로 이어지도록 했다.
- 음수 흔들림 값은 0으로 제한하고, 변형된 모든 좌표를 페그 반지름을 포함한 보드 내부로 제한한다.
- `GameWorld` 생성자에서 `PegLayoutDefinition`을 받을 수 있게 하고, 초기화와 새 게임에서 저장된 좌표 목록으로 페그를 다시 만든다.
- 기본 생성자는 기존 12×4, 80px 간격의 정확한 48개 배치를 사용해 기존 플레이 화면을 유지한다.

## 자동 검증

- 시드 `12345`를 두 번 사용한 48개 좌표가 모두 일치함을 확인했다.
- 시드 `12345`와 `54321`의 결과 중 하나 이상의 좌표가 다름을 확인했다.
- 흔들림 20px을 적용한 48개 페그가 모두 보드 내부에 있음을 확인했다.
- 3개의 좌표만 가진 사용자 정의 배치를 주입하면 대상 수와 첫 좌표가 그대로 반영됨을 확인했다.
- 사용자 정의 배치가 `ResetGame()` 후에도 3개로 다시 구성됨을 확인했다.
- Debug/Release × x64/x86 네 테스트 실행 파일이 각각 **61개 검증을 모두 통과**했다.

## 빌드·실행 검증

- 최초 빌드에서 Windows의 `max` 매크로가 표준 라이브러리 이름과 충돌하는 문제를 발견했다.
- `std::mt19937::max`는 괄호 호출로 격리하고 흔들림 하한은 조건식으로 처리한 뒤 경고 없이 재빌드했다.
- Debug/Release × x64/x86 네 구성 빌드 성공: 오류 0개, 자체 코드 경고 0개.
- Debug x64 실제 창에서 기본 12열×4행, 총 48개 페그와 기존 위치가 유지됨을 확인했다.
- 상태·안내 피드백과 캐릭터 렌더링 회귀 없이 정상 종료됐다.

## 결론

기본 게임은 기존 배치를 유지하면서도 테스트나 향후 스테이지가 좌표 데이터 또는 명시적 시드 배치를 선택할 수 있다. Sprint 1 계획 기능 구현은 모두 끝났으며 전체 회귀와 장시간 GDI 안정성 검증만 남았다.
