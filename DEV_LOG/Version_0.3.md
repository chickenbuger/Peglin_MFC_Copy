## 검증 결과

Debug x64 실행 파일을 실제 창으로 실행하고 렌더링, 발사, 일시정지, 재개, 공 초기화, 새 게임 초기화 및 종료를 확인했다. 프로세스는 테스트 중 응답 상태를 유지했으며 예외·ASSERT·오류 대화상자 없이 종료됐다.

| 검증 항목 | 결과 | 관찰 내용 |
| --- | --- | --- |
| 프로그램 시작 | 통과 | `FinalProject_Peglin` 창이 생성되고 프로세스가 `Responding=True`를 유지함 |
| 기본 화면 | 통과 | 메뉴, 툴바, 상태 표시줄, 배경, 플레이어, 적, 체력, 공, 화면 내 페그가 표시됨 |

## 확인 범위의 한계

이번 검증은 실행 가능 여부와 짧은 기본 입력 흐름을 확인한 스모크 테스트다. 다음 항목은 확인하지 않았으므로 Sprint 0 완료로 판정하지 않는다.

- 클릭 시작점과 해제점이 같은 0 길이 드래그
- 창 밖 드래그와 포커스 전환 후 마우스 캡처·커서 제한 복구
- 좌·우 벽 및 천장 충돌의 장시간 안정성
- 게임 클리어·게임 오버 전체 반복 흐름
- 10분 이상 반복 플레이 중 GDI 객체 수와 메모리 증가
- Debug/Release 및 x86/x64 사이의 실제 플레이 결과 일치
- 자체 코드 경고 0개 기준

## 관찰된 주의점

- `F5`는 공만 초기화하며 이미 반영된 몬스터 피해와 제거된 페그를 복구하지 않는다. 전체 상태 복구는 메뉴의 `새 게임`에서 정상 동작했다.
- 기존 분석에서 확인한 0 길이 드래그의 0 나눗셈 위험은 아직 수정되지 않았다.
- 빌드 시 `C4244`, `C4305`, `LNK4258` 경고가 남아 있다.

## 결론

현재 Debug x64 실행 파일은 **창을 열고 기본 게임을 조작할 수 있는 상태**다. 따라서 MFC 환경 구축 목표의 실행 가능성은 확인됐다. 다만 Sprint 0의 안정성 및 경고 제거 게이트가 남아 있으므로 다음 스프린트로 전환하지 않는다.
