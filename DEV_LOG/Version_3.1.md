# Version 3.1 — 애니메이션과 음소거 가능한 사운드 피드백

## 버전 정보

| 항목 | 값 |
| --- | --- |
| 버전 | Version 3.1 |
| 스프린트 | Sprint 3 |
| 작업일 | 2026-08-29 (Asia/Seoul) |
| 상태 | 구현 및 검증 완료 |

## 구현 이유

- 점수·콤보와 특수 페그 계산은 상단 텍스트에만 표시되어 빠른 연속 충돌 중 어떤 페그가 얼마의 보상을 만들었는지 알아보기 어려웠다.
- 효과음을 끌 수 있는 경로가 없으면 반복 플레이와 접근성 측면에서 사용자가 피드백 강도를 선택할 수 없다.

## 구현 내용

- `GameWorld`가 페그 적중, 폭탄, 새로고침, 턴 정산, 플레이어 피격과 승패를 `GameEvent`로 발행한다.
- 각 이벤트는 페그 종류, 위치, 획득 점수, 콤보, 영향받은 페그 수와 피해량을 보존한다.
- 뷰는 이벤트를 한 번만 소비해 위치에서 위로 떠오르는 0.9~1.2초 텍스트 애니메이션을 그린다.
- Normal, Critical, Bomb, Refresh와 플레이어 피해를 서로 다른 문구와 색으로 구분한다.
- 이벤트 종류에 따라 Windows 시스템 사운드를 재생하며 `M` 키로 즉시 음소거·재활성화할 수 있다.
- 상단에 현재 사운드 상태와 단축키를 항상 표시한다.
- 새 게임·승패 초기화 시 남은 애니메이션과 이벤트 큐를 정리하되 음소거 선택은 유지한다.

## 자동화 검증

- 폭탄 적중이 두 `PegHit`와 하나의 `BombTriggered` 이벤트를 만드는지 확인했다.
- 폭발로 제거된 Critical의 종류와 콤보 배율 점수가 이벤트에 유지되는지 확인했다.
- Refresh 이벤트의 복원 수, 턴 확정 점수와 이벤트 단일 소비를 검증했다.
- Debug/Release × x64/x86 앱과 테스트 빌드 성공, 오류 0개, 프로젝트 자체 경고 0개다.
- `PeglinCoreTests`: 구성별 `215 PASS / 0 FAIL`, 네 구성 총 860개 통과다.

## 실제 실행 검증

- Release x64에서 `사운드: 켜짐 (M)` 표시와 `M` 입력 후 `사운드: 꺼짐 (M)` 전환을 확인했다.
- 사운드를 다시 켠 뒤 발사해 적중 3, 콤보 3, 발사 점수 600을 확인했다.
- 충돌 위치에 `+200 · x2`, `+300 · x3`, `REFRESH +0` 애니메이션이 색상별로 표시됐다.
- 오류 대화상자, ASSERT와 잔류 프로세스 없이 정상 종료했다.
