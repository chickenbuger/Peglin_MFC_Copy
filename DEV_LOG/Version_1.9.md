## 최종 빌드·자동화 테스트

- Windows SDK `10.0.26100.0`, MSVC v143, C++20, `/W4` 기준을 유지했다.
- Debug/Release × x64/x86 네 구성에서 앱과 테스트 프로젝트를 최종 빌드했다.
- 네 구성 모두 오류 0개, 자체 코드 경고 0개다.
- Debug/Release × x64/x86 테스트 실행 파일이 각각 61개, 총 244개 검증을 통과했다.
- 마지막 빌드와 테스트 후 `git status`에 생성물 또는 소스 변경이 나타나지 않았다.

## 입력·플레이 회귀

- 같은 위치 클릭·해제 후 공이 움직이지 않고 다음 정상 발사가 가능했다.
- 비행 중 일시정지 600ms 동안 공 위치가 유지되고 재개 후 턴이 정상 정산됐다.
- 비행 중 F5는 공과 입력 상태를 조준 상태로 복구했다.
- 메뉴 새 게임은 플레이어·몬스터 체력, 공, 턴과 48개 페그를 모두 초기화했다.
- 창 경계 드래그, Alt+Tab 포커스 상실·복귀 후에도 캡처나 커서 제한이 남지 않았다.
- Debug와 Release x64의 동일 `(492,326)→(430,226)` 입력이 모두 페그 10개, 몬스터 피해 10으로 끝났다.
- ASSERT, 예외, 접근 위반과 오류 대화상자 없이 정상 종료됐다.

## 승리·패배 전체 흐름

- 실제 Release x64에서 네 번의 서로 다른 발사로 몬스터 체력을 `20→10→8→3→0`으로 만들었다.
- `Game Clear!!` 대화상자와 플레이어 100, 몬스터 20, 공과 페그의 새 게임 복귀를 확인했다.
- 페그를 피하는 수직 발사로 1~8턴 적 이동을 진행했다.
- 9~13턴에는 플레이어 피해 20이 적용되어 체력이 `100→80→60→40→20→0`이 됐다.
- `Game Over!!` 대화상자와 새 게임 상태 복귀를 확인했다.

## GDI 장시간 안정성

- Debug x64를 30초 워밍업한 뒤 10분간 1분 간격으로 GDI 객체 수를 측정했다.
- 측정 중 일반·반대·강한 각도 발사, 페그 충돌, 0 길이 취소, F5, 일시정지·재개와 두 번의 새 게임을 수행했다.
- 0~10분 표본: `34, 34, 35, 37, 34, 31, 31, 31, 33, 33, 37`
- 30초 냉각 표본: `31`
- 마지막 10분 값은 기준 대비 +3으로 허용치 +5 이하였고, 냉각 후 기준 아래로 내려가 후반 지속 상승이 없었다.
- 모든 표본에서 프로세스 `Responding=True`였다.
