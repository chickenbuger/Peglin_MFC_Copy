## P0 — Sprint 6 완료 필수 후보

- [x] 게임플레이 배경·캐릭터·몬스터·공 시각 개선과 공 이동 피드백 — Version 6.1
  - 이유: 기존 플레이 화면은 상단의 64px 임시 비트맵과 하단의 검은 배경, 단색 원형 공으로 구성돼 메뉴 화면과 시각 품질 차이가 컸고 공의 대기·이동 상태도 정지 화면에서 구분하기 어려웠다.
  - 완료 기준: ImageGen 원본과 재현 프롬프트를 보존하고, MFC 내장 리소스로 패키징하며, 캐릭터·몬스터·공의 투명 합성, 공의 대기 부유와 비행 잔상, 실제 창 검증을 완료한다.
- [x] 몬스터 종류와 멀티 몬스터 전투 로스터 — Version 6.2
  - 이유: 한 스테이지에 같은 몬스터 한 마리만 등장해 전투 장면과 스테이지 구성이 단조로웠고, 외부 콘텐츠로 적의 수와 외형을 늘릴 수 없었다.
  - 완료 기준: 최소 세 종류의 외형, 최대 세 적의 동시 표시, 현재 대상 강조, 순차 처치와 최종 Victory, 외부 로스터 검증, 이전 단일 적 데이터 복구를 네 구성과 실제 창에서 확인한다.
- [ ] 런 진행 상태와 스테이지 클리어 보상 선택
  - 이유: 현재 장비 화면은 모든 오브·유물을 자유롭게 선택하므로 플레이 결과가 성장 선택으로 이어지지 않는다.
  - 완료 기준: 새 런·스테이지 클리어·보상 3개 중 선택·다음 스테이지·런 종료·재도전의 소유권과 초기화 규칙을 모델 테스트로 고정한다.
- [ ] 오브·유물·적 효과 정의의 외부 콘텐츠 확장
  - 이유: Version 6.2에서 적 ID·이름·외형·체력은 외부화됐지만 오브·유물 카탈로그와 적별 행동·속성·효과는 아직 C++ 재컴파일이 필요하다.
  - 완료 기준: 안정적인 참조 ID, 교차 참조 검증, 중복·순환·알 수 없는 효과 거부와 내장 복구를 제공한다.
- [ ] UI 내비게이션 모델과 마우스·키보드 동등 지원
  - 이유: 공통 렌더러와 키보드 흐름은 마련됐지만 화면별 입력 분기와 포커스 규칙이 뷰에 직접 남아 있고 마우스 메뉴 선택이 없다.
  - 완료 기준: 선택·확인·취소 의미를 공통 모델로 분리하고 키보드와 마우스로 같은 기능을 수행하며 포커스 표시와 작은 클라이언트 크기를 검증한다.
- [ ] 문자열 리소스·지역화 및 자산 빌드 파이프라인
  - 이유: 한글·영문 문자열과 이미지 변환 절차가 소스와 수동 기록에 분산돼 콘텐츠가 늘수록 일관성 검증이 어렵다.
  - 완료 기준: UTF-8 문자열 카탈로그, 누락 키 복구, BMP 변환·크기·색심도 검사와 패키지 포함 검사를 자동화한다.
- [ ] 런 조합 회귀·실행·GDI·최종 패키지 검증
  - 이유: 보상·외부 효과·입력·지역화가 결합되면 저장 호환성과 화면 전환 회귀 위험이 커진다.
  - 완료 기준: 네 구성, 대표 런의 승리·패배·중단·재개, 저장 마이그레이션, 10분 GDI와 앱 로컬 패키지를 모두 검증한다.
