## P0 — Sprint 10

- [x] 공식 Peglin 플레이 흐름 참고 전투 UI·영상 프레젠테이션 개선 — Version 10.1
  - 이유: 현재 기능은 완성되어도 장문 상태 패널, 원색 페그와 짧은 전투 이펙트 때문에 실제 플레이와 포트폴리오 영상에서 턴 흐름과 타격감이 충분히 전달되지 않았다.
- [ ] 개인정보를 포함하지 않는 회전식 진단 로그와 오류 코드
  - 이유: 현재 UI 알림과 테스트는 즉시 확인에는 충분하지만 배포 환경의 저장·오디오·콘텐츠 실패를 사후 재현하기 어렵다.
- [ ] 런 시드 표시·복사와 결정적 리플레이 입력 기록
  - 이유: 같은 보드와 선택 경로에서 발생한 물리·전투 문제를 개발자와 사용자가 정확히 공유할 수 있어야 한다.
- [ ] 오브·유물 도감과 획득 이력
  - 이유: 콘텐츠가 5종씩으로 늘었지만 런 밖에서 효과와 발견 상태를 비교할 영구 화면이 없다.
- [ ] 콘텐츠 제작 오류의 파일·줄·항목 인게임 표시
  - 이유: 핫 리로드는 안전하게 거부하지만 제작자가 원인을 수정하려면 현재보다 구체적인 위치 정보가 필요하다.
- [ ] 스테이지·보상·상점 전환의 접근성 애니메이션 설정
  - 이유: 화면 전환 완성도를 유지하면서 멀미·시각 민감 사용자가 이동량과 섬광을 줄일 수 있어야 한다.
- [ ] Sprint 10 결합 회귀·진단 정보 검토·최종 배포
  - 이유: 로그와 리플레이가 사용자 경로, 계정명 등 민감 정보를 노출하지 않는지 포함해 최종 패키지에서 검증해야 한다.

## 진행 규칙

1. Version 10.1부터 계획 순서대로 진행한다.
2. 기능 하나당 `구현 → 네 구성 빌드·테스트 → 실행 검증 → Version 문서 → 커밋·푸시 → Notion`을 유지한다.
3. Sprint 종료 시 계획 전체 목록과 각 항목의 완료 여부를 반드시 표출한다.
4. 사용자 승인 전에는 Sprint 10 기능을 구현하지 않는다.
